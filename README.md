# VPN Health Monitor

Приложение для Windows, которое проверяет, что VPN действительно работает, — и, если попросить, не даёт выбранным программам выходить в интернет мимо него.

Проверка идёт снаружи, а не по значку VPN-клиента: какой у вас сейчас внешний IP, в какой стране, через какого провайдера, куда уходит трафик по умолчанию, доступен ли интернет вообще. Если VPN отвалился, а клиент по-прежнему показывает «подключено», приложение это заметит.

## Прежде чем ставить — что нужно знать

Приложение умеет **менять правила брандмауэра Windows**. Это его главная функция и главный риск.

Если вы включите защиту для программы, для неё будет создано постоянное правило «блокировать прямой выход в интернет». Оно живёт в брандмауэре само по себе: продолжает действовать после закрытия приложения, после перезагрузки и **после удаления самой программы**, если удалять неправильно. Через полгода «почему у меня браузер не грузит страницы» уже не связывается с приложением, которое ставили давно.

Поэтому три вещи стоит прочитать до установки, а не после:

- **Как снять защиту**, если что-то пошло не так, — раздел [«Пропал интернет — как вернуть»](#пропал-интернет--как-вернуть). Там три способа, включая аварийный скрипт, который работает, даже когда приложение не запускается.
- **Что приложение не проверяли** — раздел [«Где это не проверялось»](#где-это-не-проверялось). Четыре конфигурации, до которых у автора не было доступа.
- **Защита по умолчанию выключена.** Список защищаемых программ пуст, никакие правила не создаются, пока вы сами не добавите программу и не нажмёте «Применить правила».

Мониторинг сам по себе брандмауэр не трогает — он только смотрит и показывает.

## Установка

1. Скачайте установщик: **[VpnHealthMonitor-Setup.exe](https://github.com/afest/vpn-health-monitor/releases/latest/download/VpnHealthMonitor-Setup.exe)** (~47 МБ) — или со [страницы релизов](https://github.com/afest/vpn-health-monitor/releases/latest).
2. Запустите. Права администратора для установки **не нужны** — программа ставится в вашу папку пользователя (`%LOCALAPPDATA%\Programs\VpnHealthMonitor`). Установщик создаёт ярлык в меню «Пуск», ярлык на рабочем столе — по желанию, галкой.
3. При первом запуске появится короткий экран: что делает kill switch, зачем нужны права администратора и где кнопка возврата интернета. Показывается один раз.

Отдельно ставить .NET не нужно — он внутри. Из-за этого установщик весит 47 МБ, а на диске занимает около 154 МБ; это плата за то, что установка — один шаг.

Windows 10 или 11, 64-разрядная.

### Windows скажет, что приложение небезопасно

При первом запуске появится синий экран **«Система Windows защитила ваш компьютер»**. Чтобы установить: **«Подробнее» → «Выполнить в любом случае»**.

Это не признак заражения. Так Windows реагирует на любую программу, подписанную не купленным сертификатом: SmartScreen доверяет издателям с историей загрузок и платной подписью. Сертификат стоит денег ежегодно, для этого проекта он не покупался — поэтому предупреждение будет и дальше.

Проверить файл, не полагаясь на слово автора, можно двумя способами:

- Отчёт **[VirusTotal для текущего установщика](https://www.virustotal.com/gui/file/650bb9c0aa52ad7ed04c0bde434d648eb1ff99d2181160b2b1d9a90f6920bf5c)** — 70+ антивирусных движков.
- Сверить, что скачали именно проверенный файл:

  ```powershell
  Get-FileHash .\VpnHealthMonitor-Setup.exe -Algorithm SHA256
  ```

  Хеш должен совпасть с SHA-256 в описании релиза.

**Антивирусы тоже могут возражать — в том числе встроенный Defender.** На VirusTotal установщик помечают несколько движков, включая Microsoft (`Program:Win32/Wacapew.C!ml`). Суффикс `!ml` означает «решила модель машинного обучения», а не «найден известный вирус»: ни одной сигнатуры конкретного вредоноса ни один движок не даёт. Так реагируют на сочетание примет — неподписанный установщик, распаковка исполняемого файла, программа, которая правит брандмауэр.

Если Defender удалил скачанный файл: «Безопасность Windows» → «Защита от вирусов и угроз» → «Журнал защиты» → найти файл → «Восстановить». Заставлять себя это делать не нужно — если сомневаетесь, разумнее собрать программу из исходников самому (раздел [«Сборка из исходников»](#сборка-из-исходников)): код открыт целиком, сборка занимает одну команду.

## Что показывает мониторинг

Нажмите «Проверить сейчас» — приложение опросит внешние сервисы и покажет: внешний IPv4 и IPv6, страну, провайдера (ASN), DNS-серверы, задержку и потери пакетов, какой сетевой интерфейс сейчас основной. «Старт мониторинга» повторяет проверку по расписанию и складывает события в лог; значок в трее меняет цвет.

Верхняя плашка — итог проверки:

| Статус | Что значит |
|---|---|
| `OK` | Интернет есть, включённые проверки проходят, скорость в норме |
| `РИСК УТЕЧКИ` | Страна, IP, провайдер или маршрут не те, что вы задали; либо виден внешний IPv6 при запрете |
| `IP ИЗМЕНИЛСЯ` | Внешний IP сменился относительно сохранённого, но страна прежняя |
| `СТРАНА ИЗМЕНИЛАСЬ` | Страна другая, но проверка по стране выключена |
| `СЕТЬ ПРОСЕЛА` | С IP всё в порядке, но ping или потери выше порогов |
| `ПРОВЕРКА НЕ УДАЛАСЬ` | Интернет вроде есть, но сервисы определения IP не ответили |
| `НЕТ ИНТЕРНЕТА` | Не проходят ни HTTP, ни ping, внешний IP получить не удалось |

Ни одна проверка не включена «на всякий случай»: по умолчанию поле «Ожидаемая страна» пустое, и приложение не считает риском то, чего вы не задавали.

### Какую проверку выбрать под свой VPN

Проверок пять, и работают они в разных ситуациях:

- **Риск по стране** — VPN выводит в другую стране, чем ваша. Самая простая и надёжная. Заполните «Ожидаемая страна» (`SE`, `Sweden` или `Швеция`).
- **Риск по IPv4** — жёстко фиксирует конкретный адрес. Годится, только если у VPN статический IP; при ротации выходных адресов будет постоянно краснеть.
- **Риск по маршруту VPN** — замечает, что трафик по умолчанию ушёл с VPN-адаптера. **Работает только с VPN в режиме TUN.** В режиме системного прокси маршрут не меняется никогда, и проверка честно напишет «не применима» вместо того, чтобы вечно показывать зелёное.
- **Риск по провайдеру** — сравнивает провайдера выхода со списком разрешённых. Единственная проверка, которая ловит обрыв, **когда VPN выводит в вашей же стране**: страна не меняется, маршрут в прокси-режиме тоже, а провайдер при обрыве становится домашним. Выключена по умолчанию — сначала наберите список кнопкой «Добавить текущего провайдера».
- **IPv6 leak check** — ищет внешний IPv6 в обход туннеля.

Для типичного VPN без статического IP: «Ожидаемая страна» + риск по стране + риск по маршруту, риск по IPv4 выключен. Тогда смена адреса внутри страны не будет ложной тревогой, а выключение VPN — будет.

## Kill switch: запрет выхода мимо VPN

Вкладка «Защищённые приложения» включает для выбранных программ режим «закрыто по умолчанию»: прямой выход в интернет заблокирован заранее, остаётся только путь через VPN.

**Функция необязательная.** По умолчанию список пуст, правила не создаются.

### Как это устроено

Для каждой выбранной программы создаётся постоянное правило брандмауэра: блокировать исходящие соединения этой программы **на физических адаптерах** (Wi-Fi, Ethernet, встроенный LTE-модем, USB-адаптеры). VPN-адаптер и локальная петля не блокируются.

- **VPN в режиме TUN** — трафик идёт через TUN-адаптер, он не заблокирован → программа работает.
- **VPN в режиме системного прокси** — трафик идёт через локальный прокси → программа работает.
- **VPN выключен** — остаётся только прямой путь, а он закрыт → **выхода нет.**

Приложение не участвует в передаче пакетов и не «ловит момент обрыва». Правило статично и действует всегда: в том числе если VPN-клиент упал, если сам монитор закрыт или если Windows только что загрузилась. Окна, в котором трафик успевает утечь, здесь нет по конструкции.

**Перед применением правил приложение показывает список адаптеров и ждёт подтверждения.** Это важный экран, а не формальность: если ваш VPN-клиент ставит адаптер, неотличимый от обычного Ethernet (так делают корпоративные клиенты), снимите с него галку — иначе защищённая программа потеряет доступ и при включённом VPN. Пропущенный адаптер — наоборот, дыра. Список переспрашивается, когда набор адаптеров в системе изменился: воткнули модем, приехали в док-станцию.

Права администратора нужны только на само применение и снятие правил — один запрос UAC на операцию. Всё остальное время приложение работает без повышения прав.

### Чего kill switch не может

- **Нельзя «разрешить ровно один VPN-адаптер».** В брандмауэре Windows запрет сильнее разрешения, поэтому модель построена как «блокировать прямой выход», а не «разрешить только туннель».
- **Защита привязана к адаптерам на момент применения.** Появился новый физический интерфейс — нажмите «Применить правила» ещё раз.
- **Классификация адаптеров — эвристика** по типу среды, признаку виртуальности и имени. Она может ошибиться в обе стороны — поэтому последнее слово оставлено человеку на экране подтверждения.
- **Программы, которые ходят в сеть через общий `node.exe`** (или другой общий процесс-хост), защитить нельзя: блокировка общего интерпретатора перекрыла бы все программы на нём разом.
- **В режиме системного прокси** работать будут только те программы, которые этот прокси используют. Программа, игнорирующая системный прокси, окажется отрезана полностью.
- Это **не** перехват трафика, не VPN-клиент и не антивирус. Приложение только создаёт и снимает правила брандмауэра и читает их состояние.

### Программы, у которых несколько исполняемых файлов

Некоторые программы ходят в сеть не тем файлом, который вы запускаете. Тогда одной строки в списке мало.

Проверенный случай — расширения редакторов кода: заблокирован основной `Code.exe`, а расширение продолжает работать, потому что запускает собственный вспомогательный файл в своей папке. Такие файлы нужно добавлять отдельными строками. Как отличить работающую блокировку от кажущейся: `Failed to fetch`, таймаут, `error sending request` — прямой выход закрыт; ответ `403` с заголовком `cf-ray` означает, что запрос **дошёл** до сервера, то есть какой-то путь остался открытым.

Программы, которые обновляются в папку с номером версии, приложение отслеживает: после обновления статус станет «Путь устарел», кнопка «Обновить путь» перепривяжет правило.

## Пропал интернет — как вернуть

Правила kill switch живут в брандмауэре Windows независимо от приложения: они действуют после его закрытия, после перезагрузки и после удаления, если удалить неаккуратно. Если какая-то программа перестала выходить в сеть — вот три способа снять защиту, от простого к аварийному.

**1. Из приложения.** Вкладка «Защищённые приложения» → кнопка **«Отключить защиту»** → подтвердить UAC. Снимаются все правила приложения разом.

**2. Аварийным скриптом** — когда приложение не открывается, не установлено или непонятно, что происходит. В папке программы (`%LOCALAPPDATA%\Programs\VpnHealthMonitor\tools\`) лежит:

```text
remove-protection.bat
```

Двойной клик. Скрипт сам запросит права администратора, покажет найденные правила, снимет их и скажет, сколько осталось. Повторный запуск безопасен. Посмотреть, что он собирается удалить, ничего не меняя:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\remove-protection.ps1 -DryRun
```

**3. Руками через `netsh`** — если нет и скрипта. Посмотреть правила (работает **без** прав администратора):

```powershell
netsh advfirewall firewall show rule name=all dir=out | findstr /C:"VPN Health Monitor"
```

Удалить конкретное правило — уже от администратора, имя копируется из вывода выше целиком, вместе со скобками:

```powershell
netsh advfirewall firewall delete rule name="VPN Health Monitor - Block Direct - firefox.exe [016ac999]"
```

Во всех трёх вариантах удаляются **только** правила с префиксом `VPN Health Monitor - `. Чужие правила брандмауэра не затрагиваются.

> **Почему не `Get-NetFirewallRule`.** Эта команда подводит ровно в аварийной ситуации: без прав администратора она возвращает **ноль правил** — выглядит так, будто снимать нечего, хотя правила есть и работают. Плюс имена правил содержат `[хеш]` в квадратных скобках, а `-DisplayName` трактует их как шаблон и точное имя не находит. `netsh` показывает те же правила без администратора и не страдает ни от того, ни от другого.

## Удаление

Через «Параметры → Приложения» или повторным запуском установщика. Деинсталлятор **снимает все правила kill switch** — на этом шаге будет один запрос UAC, даже если установка прав не требовала. Если правила почему-то остались, раздел выше работает независимо от того, установлена программа или нет.

## Где это не проверялось

Приложение писалось и проверялось на одной машине: Windows 10, домашняя сеть, VPN-клиент в режиме TUN. Ниже — конфигурации, до которых у автора **не было доступа**. Это не «известные баги», а честное «не знаю»: код их учитывает, но вживую никто не проверял.

- **Встроенный LTE/WWAN-модем.** Классификация адаптеров написана так, чтобы такой модем считался физическим и попадал под блокировку, но проверить это на живом модеме не удалось. Если модем окажется не распознан, kill switch будет показывать «Защищено», а прямой выход через модем останется открытым. На экране подтверждения адаптеров видно полный список — если своего модема там нет, отметьте его вручную.
- **Корпоративный VPN с виртуальным Ethernet-адаптером.** Такие клиенты ставят адаптер, который выглядит как обычная сетевая карта. Эвристика может отнести его к физическим и заблокировать — тогда защищённая программа потеряет доступ даже при включённом VPN. Лечится снятием галки на экране подтверждения.
- **VPN в режиме прокси без TUN-адаптера.** Kill switch по конструкции работать должен: локальная петля не блокируется. Проверка «риск по маршруту» в этом режиме честно объявляет себя неприменимой — но всё это выведено из кода, а не снято на живой конфигурации.
- **Сеть, где заблокированы Google и Cloudflare.** Адреса проверок доступности и определения IP вынесены в настройки именно для такого случая, значения по умолчанию можно заменить целиком. Прогон в такой сети не делался.

Если попробуете в одной из этих конфигураций — расскажите в [Issues](https://github.com/afest/vpn-health-monitor/issues), что получилось. Особенно интересен первый случай.

Отдельно: **интерфейс приложения только на русском.** Английской локализации нет.

## Приватность

Приложение не перехватывает трафик, не работает как прокси или VPN-клиент, не читает ваши файлы и не записывает, какие сайты вы открываете.

Наружу уходят только запросы, нужные для самой диагностики, — и все они `GET`, без отправки каких-либо ваших данных:

| Зачем | Адреса |
|---|---|
| Внешний IPv4 и страна/провайдер | `api.ipify.org`, `ifconfig.me`, `ipinfo.io`, `ipapi.co`, `ipwho.is` |
| Внешний IPv6 | `api6.ipify.org`, `ifconfig.co`, `icanhazip.com` |
| Доступность интернета | `cloudflare.com/cdn-cgi/trace`, `google.com/generate_204`, `msftconnecttest.com` |
| Задержка и потери | ICMP-ping на `1.1.1.1` и `8.8.8.8` |

Эти сервисы по своей природе видят ваш IP-адрес — так и работает определение внешнего IP. **Все адреса редактируются в настройках**, включая полную замену на свои.

Никакой телеметрии, аналитики и автообновления в приложении нет: других исходящих соединений код не делает. DNS-серверы читаются локально из настроек Windows. Настройки и логи хранятся только у вас:

```text
%LOCALAPPDATA%\VpnHealthMonitor\settings.json
%LOCALAPPDATA%\VpnHealthMonitor\logs\vpn-health-monitor-ГГГГ-ММ-ДД.jsonl
```

В лог пишутся события (смена статуса, смена IP, потеря и восстановление связи), а не каждый запрос. «Export CSV» выгружает тот же лог в таблицу.

## Для разработчиков

### Сборка из исходников

Нужен .NET 8 SDK, Windows 10/11.

```powershell
dotnet build .\VpnHealthMonitor.sln -c Release
dotnet run --project .\VpnHealthMonitor\VpnHealthMonitor.csproj
```

Такая сборка — framework-dependent: для запуска нужен установленный .NET 8 Desktop Runtime. Артефакты — в `VpnHealthMonitor\bin\Release\net8.0-windows\`.

### Сборка установщика

```powershell
powershell -ExecutionPolicy Bypass -File .\installer\build.ps1
```

Скрипт делает два шага: `dotnet publish` self-contained + single-file в `publish\win-x64\`, затем компилирует `installer\VpnHealthMonitor.iss` через [Inno Setup 6](https://jrsoftware.org/isinfo.php) (`winget install --id JRSoftware.InnoSetup`). Результат — `installer\Output\VpnHealthMonitor-Setup-<версия>.exe`.

Публикация каждый раз чистится перед сборкой: у `dotnet publish` есть инкрементальный кэш, который при повторном запуске в тот же каталог иногда молча пропускает копирование `tools\remove-protection.*` — и установщик собирается без аварийного скрипта.

Версия задаётся в двух местах, их нужно держать в паре: `<Version>` в `VpnHealthMonitor.csproj` и `MyAppVersion` в `installer\VpnHealthMonitor.iss`.

Иконка приложения генерируется скриптом `tools\make-icon.ps1` — собственная отрисовка из примитивов, чтобы не тянуть в поставку графику неизвестного происхождения.

### Тесты

```powershell
dotnet test .\VpnHealthMonitor.sln
```

173 теста. Покрыты преимущественно чистые функции: матрица статусов `HealthEvaluator.Evaluate` (golden-master на приоритеты, 21 случай) и разбор путей для kill switch — `AppxPathResolver`, `FirewallService.BuildRuleName`/`PathsMatch`, `CliPathResolver`. Сетевой слой и UI не тестируются сознательно. Исключение — `CliPathResolver.ResolveMovedPaths`: для kill switch молчаливый сбой недопустим, поэтому резолв пути проверяется на временной файловой структуре.

### Зависимости

Основное приложение собирается **на чистом .NET SDK, без единого пакета NuGet**. xUnit подключён только в тест-проекте и в поставку не попадает. Подробности — в [NOTICE.md](NOTICE.md).

### Структура

- `VpnHealthMonitor/` — приложение (WPF): `Models/` — данные, `Services/` — сетевые проверки, брандмауэр, настройки, логи, оценка состояния.
- `VpnHealthMonitor.Tests/` — тесты (xUnit).
- `tools/` — аварийное снятие правил (`remove-protection.ps1`/`.bat`), генератор иконки.
- `installer/` — Inno Setup: скрипт установщика и сборка.
