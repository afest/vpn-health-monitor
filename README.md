# VPN Health Monitor

Windows WPF MVP для проверки фактического состояния VPN/интернета снаружи: внешний IPv4/IPv6, страна, ASN/provider, DNS-серверы Windows, HTTP availability, ping/packet loss, baseline IP, tray-индикатор, Windows-уведомления, событийные JSONL-логи и CSV-экспорт.

## Быстрый запуск

```powershell
dotnet build .\VpnHealthMonitor.sln
dotnet run --project .\VpnHealthMonitor\VpnHealthMonitor.csproj
```

Собранный exe оказывается в `VpnHealthMonitor\bin\Debug\net8.0-windows\VpnHealthMonitor.exe` (или `Release\...` при сборке с `-c Release`) — можно создать ярлык на него.

Приложение запускается как обычное Windows-окно и сразу показывает tray icon. Основные действия: `Проверить сейчас` для ручной проверки, `Старт мониторинга` для периодического мониторинга, `Текущий IP как baseline` для сохранения нормальной точки: внешний IP, страна и VPN/default-route интерфейс, `Export CSV` для выгрузки JSONL-событий в CSV.

По умолчанию `Ожидаемая страна` пустая, чтобы приложение не считало leak risk по стране до явной настройки. Если нужен контроль конкретной VPN-локации, укажи country code или название, например `SE` / `Sweden` / `Швеция`.

В Settings можно отдельно выбрать, что считать риском:

- `Риск по стране` — другая страна относительно `Ожидаемая страна` дает `РИСК УТЕЧКИ`.
- `Риск по IPv4` — IP вне `Ожидаемые IPv4` или запрещенная смена baseline IP дает `РИСК УТЕЧКИ`.
- `Риск по маршруту VPN` — если default route ушел с сохраненного VPN-интерфейса на обычный Wi-Fi/адаптер, это `РИСК УТЕЧКИ`, даже если IP/geo API в этот момент не ответили. **Проверка работает только для VPN в режиме TUN.** В режиме системного прокси default route не меняется никогда, и сравнение не сработает ни при каком состоянии VPN — поэтому в блоке `Текущая сеть` есть строка `Проверка маршрута`: она честно пишет «не применима», если ожидаемый интерфейс не похож на VPN-адаптер. В таком режиме полагайся на `Ожидаемая страна` и внешний IP.
- `IPv6 leak check` — приложение пробует получить внешний IPv6 через IPv6-only endpoint'ы. Если `Разрешить внешний IPv6` выключен, найденный внешний IPv6 дает `РИСК УТЕЧКИ`.
- `Риск по провайдеру` — если провайдер выхода не входит в список `Разрешённые провайдеры`, это `РИСК УТЕЧКИ`. Единственная проверка, которая работает, когда VPN выходит в твоей же стране: страна не меняется, маршрут в прокси-режиме тоже, а провайдер при обрыве туннеля становится домашним. Выключено по умолчанию — включай, когда наберёшь список. Кнопка `Текущий IP как baseline` и кнопка `Добавить текущего провайдера` пополняют его; если VPN переключает выходы между хостерами, добавь их все. Сравнение терпимо к написанию (`M247 Europe SRL`, `M247 Ltd` и `M247` — один провайдер) и молчит, когда провайдер не определён.
- `Enable DNS check` — показывает DNS-серверы, которые Windows видит на активных сетевых интерфейсах. DNS сам по себе не помечается красным: без надежной эталонной базы это informational/warning-поверхность.
- `Windows notifications` — показывает уведомления при `РИСК УТЕЧКИ`, `IP ИЗМЕНИЛСЯ`, `НЕТ ИНТЕРНЕТА` и восстановлении `OK`. Есть cooldown 60 секунд, чтобы не спамить.
- `Закрывать в трей` — если мониторинг запущен, закрытие окна прячет приложение в tray, мониторинг продолжает работать. Выйти полностью можно через контекстное меню tray icon.

Для VPN без статического IP обычно удобный режим такой: `Ожидаемая страна = Швеция`, `Риск по стране = on`, `Риск по IPv4 = off`, `Риск по маршруту VPN = on`. Тогда ротация IP внутри Швеции не будет красной аварией, но выключение VPN будет красным риском.

Индикаторы работают так:

- `OK` зеленый — включенные проверки риска проходят. Если IP меняется, но `Unexpected IPv4 risk` выключен, это остается зеленым `OK` с пояснением в описании.
- `РИСК УТЕЧКИ` красный — сработала включенная проверка риска по стране, IPv4 или VPN/default-route интерфейсу.
- `РИСК УТЕЧКИ` красный также появляется, если включен IPv6 leak check, внешний IPv6 виден наружу, а `Разрешить внешний IPv6` выключен.
- `СТРАНА ИЗМЕНИЛАСЬ` желтый — страна изменилась, но `Country mismatch risk` выключен.
- `СТРАНА НЕ ОПРЕДЕЛЕНА` серый — страну не удалось определить, но риск по стране выключен.
- `IP ИЗМЕНИЛСЯ` желтый — `Unexpected IPv4 risk` включен, но смена IP внутри ожидаемой страны разрешена.
- `СЕТЬ ПРОСЕЛА` желтый — IP/страна в порядке, но ping или packet loss выше порогов.
- `ПРОВЕРКА НЕ УДАЛАСЬ` фиолетовый — интернет есть, но нужная проверка IP/geo не дала корректного результата; если при этом маршрут ушел с VPN-интерфейса, статус будет красным `РИСК УТЕЧКИ`.
- `НЕТ ИНТЕРНЕТА` красный — не проходят HTTP/ping и не удалось получить внешний IP.

## Как проверить MVP

1. Запусти приложение через ярлык `VPN Health Monitor.lnk`.
2. Нажми `Проверить сейчас`. В блоке `Текущая сеть` должны появиться внешний IPv4, страна, ASN/provider и активный интерфейс. Если поля остались `Неизвестно`, смотри верхний статус и `Последние события`.
3. Если текущий VPN/IP нормальный, нажми `Текущий IP как baseline`. В поле `Baseline` должен появиться текущий IPv4, страна, время и VPN-интерфейс; поле `Ожидаемый VPN-интерфейс` тоже заполнится. Это поле — выпадающий список реальных адаптеров машины, можно выбрать свой VPN-адаптер вручную или вписать часть имени.
4. Нажми `Проверить сейчас` еще раз. Если страна ожидаемая, статус должен быть `OK` или `СЕТЬ ПРОСЕЛА`. `СЕТЬ ПРОСЕЛА` означает, что сеть есть, но ping/loss выше порогов.
5. Нажми `Старт мониторинга` на 1-2 минуты. В `Статистика сессии` должны обновляться `Здоровое время`, `Инциденты` и `Время проблем`, а в `Последние события` должны появляться только события: старт, стоп, смена статуса, смена IP, потеря/восстановление интернета.
6. Проверь tray icon: зеленый для `OK`, желтый для предупреждений/ошибок проверки, красный для `РИСК УТЕЧКИ` и `НЕТ ИНТЕРНЕТА`. Левый клик по tray icon открывает окно, tooltip показывает текущий статус и IPv4.
7. В Settings включи/выключи `IPv6 leak check` и `Enable DNS check`, затем нажми `Проверить сейчас`. В сводке должны появиться внешний IPv6 или `Не обнаружен / проверка не прошла`, а также DNS-серверы или понятное сообщение, что они не обнаружены/проверка выключена.
8. Нажми `Стоп мониторинга`, затем `Открыть папку логов`. В папке должен быть JSONL-файл за сегодня с событиями.
9. Нажми `Export CSV`. Рядом с JSONL появится файл `vpn-health-monitor-export-YYYYMMDD-HHMMSS.csv`.

Проверка смены IP:

1. Сначала выставь baseline на текущем VPN через `Set Current IP as Baseline`.
2. Переключи VPN на другую локацию или переподключи конфигурацию, которая дает другой внешний IP.
3. Нажми `Run Check Now`.
4. Если страна совпадает и `Риск по IPv4` выключен, ожидаемый результат — зеленый `OK` с пояснением, что IPv4 изменился внутри ожидаемой страны.
5. Если в Settings задана `Ожидаемая страна`, а новый VPN вышел в другую страну, ожидаемый результат — `РИСК УТЕЧКИ`.
6. Если включить `Риск по IPv4` и запретить смену IP внутри страны, то смена IP относительно baseline должна давать `РИСК УТЕЧКИ`, даже если страна та же.

Проверка выключения VPN:

1. Включи VPN, выставь `Ожидаемая страна`, нажми `Проверить сейчас`, затем `Текущий IP как baseline`.
2. Проверь, что в `Ожидаемый VPN-интерфейс` указан VPN/TUN-адаптер, например `Karing TUN Network Adapter`.
3. Нажми `Старт мониторинга`.
4. Полностью выключи VPN.
5. Ожидаемый результат: верхняя плашка становится красной `РИСК УТЕЧКИ`. Если IP/geo API успели ответить, в `Страна` будет текущая страна; если API временно не ответили, описание все равно скажет, что default route ушел с ожидаемого VPN-интерфейса.

Проверка IPv6:

1. В Settings включи `IPv6 leak check`.
2. Если внешний IPv6 допустим для твоей VPN-конфигурации, оставь `Разрешить внешний IPv6` включенным.
3. Если внешний IPv6 не должен выходить наружу, выключи `Разрешить внешний IPv6` и нажми `Проверить сейчас`.
4. Если IPv6 endpoint'ы увидят публичный IPv6, ожидаемый результат — красный `РИСК УТЕЧКИ`. Если IPv6 нет или он недоступен с машины, в UI будет `Не обнаружен / проверка не прошла` без красного статуса.

Важный нюанс для VPN-пулов:

- Один и тот же VPN-профиль может отдавать разные внешние IPv4 разным сайтам, даже если ты не переключал VPN руками.
- Смотри поле `Результаты IP API`: если разные IP-сервисы показывают разные адреса, это ротация/балансировка egress-IP или разные правила маршрутизации по доменам.
- Для таких VPN не стоит включать `Unexpected IPv4 risk` на один точный IP, иначе будут частые `LEAK RISK`. Лучше проверять `Expected country` и provider/ASN, а список IP оставить пустым или добавить все реально допустимые IP.

Как понять, что работает:

- `OK` — интернет доступен, внешний IPv4 получен, включенные проверки риска не конфликтуют с текущей VPN-локацией, ping/loss в норме.
- `IP ИЗМЕНИЛСЯ` — приложение заметило смену внешнего IPv4 относительно baseline, и настройки считают это предупреждением.
- `РИСК УТЕЧКИ` — текущая страна, IP или default route не совпадают с тем, что явно задано/сохранено в Settings.
- `НЕТ ИНТЕРНЕТА` — не проходят HTTP/ping и не получается получить внешний IP.
- `ПРОВЕРКА НЕ УДАЛАСЬ` — интернет вроде есть, но IP/geo API не ответили корректно.
- `СЕТЬ ПРОСЕЛА` — IP выглядит корректно, но качество сети хуже заданных порогов.

## Защищённые приложения (per-app kill switch)

Вкладка `Защищённые приложения` включает для выбранных `.exe` режим «закрыто по умолчанию»: их прямой выход в интернет блокируется заранее, разрешён только путь через VPN. Это **опциональная** функция, по умолчанию список пуст и никакие правила не создаются.

### Как это работает

Для каждого выбранного `.exe` создаётся постоянное правило Windows Firewall: **Block, Outbound, Program = путь к exe, привязка к физическим адаптерам**. Loopback и VPN/TUN-адаптер остаются на разрешении по умолчанию.

Физическим считается всё, что не распознано как VPN-туннель или виртуальный адаптер: Wi-Fi, Ethernet, Bluetooth-тетеринг, **встроенный LTE/WWAN-модем**, USB-адаптеры. Раньше список собирался наоборот — по белому списку типов среды (`802.3`/`802.11`/`Bluetooth`), и мобильный модем в него не попадал: правило для него не создавалось, а интерфейс показывал `Защищено`.

**Перед применением правил приложение показывает список адаптеров и ждёт подтверждения.** Отметки расставлены по типу адаптера, но их можно менять: если твой VPN-клиент ставит адаптер, неотличимый от обычного Ethernet (так делают корпоративные клиенты), сними с него отметку — иначе защищённая программа потеряет доступ и с включённым VPN. Пропущенный адаптер — наоборот, дыра в защите. Подтверждённый список виден на вкладке `Защищённые приложения` и переспрашивается заново, когда набор адаптеров в системе изменился (воткнули USB-модем, приехали в док-станцию).

- **VPN в режиме TUN:** трафик приложения идёт через TUN-адаптер (его нет в списке блокировки) → работает.
- **VPN в режиме системного прокси:** приложение ходит через локальный прокси (loopback, не заблокирован) → работает.
- **VPN выключен:** остаётся только прямой путь через физический адаптер, а он заблокирован → **прямого выхода нет (fail-closed).**

Правило статично и всегда активно после применения. Приложение VPN Health Monitor **не участвует** в передаче пакетов — поэтому нет «окна гонки» вида «заметили разрыв → блокируем»: блокировка прямого пути действует всегда, в том числе если VPN-клиент крашнулся, а само приложение VPN Health Monitor закрыто или Windows перезагружен.

### Права администратора

Применение/снятие правил требует прав администратора. Само приложение работает без повышения прав; для операций с firewall оно запускает вспомогательный PowerShell-скрипт через UAC (по одному запросу UAC на операцию). Если UAC отклонён — операция не выполняется, ошибка показывается и логируется, приложение не падает.

### Имена правил и хранение

- Правила: `VPN Health Monitor - Block Direct - <имя_exe> [hash]`.
- Список защищённых программ хранится в `settings.json` (`ProtectedApps`).
- Кнопки: `Добавить программу`, `Применить правила`, `Отключить защиту`, `Обновить статус`, плюс по строке — `Переустановить`, `Удалить` и (при смене пути после обновления) `Обновить путь`.
- Статусы: `Защищено`, `Правила не применены`, `Файл не найден`, `Путь устарел`, `Ошибка`.

### Ограничения (важно и честно)

- Windows Firewall **не умеет** «разрешить ровно один конкретный VPN-адаптер»: Block имеет приоритет над Allow, поэтому модель построена как «блок прямого выхода на физических адаптерах», а не «allow только TUN».
- Защита привязана к набору **физических** адаптеров на момент применения. Если появится новый физический интерфейс (например, USB-модем/телефон) — нужно нажать `Применить правила` ещё раз, иначе он не будет покрыт. При следующем применении или обновлении пути приложение заметит изменившийся набор и снова покажет экран подтверждения.
- Классификация адаптеров — эвристика по типу среды, флагу `Virtual` и имени. Она может ошибиться в обе стороны, поэтому последнее слово оставлено человеку на экране подтверждения: там видно и что блокируется, и что остаётся разрешённым.
- В режиме **системного прокси** рабочими остаются только программы, которые этот системный прокси используют. Программа, которая прокси игнорирует, будет полностью заблокирована (прямой путь закрыт, прокси не использует).
- Подходит для **Claude Code CLI**: современный CLI ставится как самостоятельный `claude.exe`, а не скрипт поверх общего `node.exe`, поэтому блокируется по пути как любая программа. CLI самообновляется в версионную папку `...\Claude\claude-code\<версия>\claude.exe` — приложение следит за этим так же, как за Store/MSIX: при смене версии статус становится `Путь устарел`, всплывает алерт, а кнопка `Обновить путь` пере-привязывает правило на новый путь (один UAC). Чтобы путь не «уезжал» сам в фоне (и защита не отваливалась незаметно между обновлениями), авто-апдейт CLI лучше отключить: `DISABLE_AUTOUPDATER=1` в пользовательских переменных окружения — тогда обновление только вручную.
- Для **VS Code AI-расширений** недостаточно добавить только `Code.exe`: расширение может запускать отдельный helper/sidecar `.exe`, который сам ходит в сеть. Проверенные примеры: OpenAI ChatGPT/Codex extension запускает `...\openai.chatgpt-...\bin\windows-x86_64\codex.exe`, Anthropic Claude Code extension — `...\anthropic.claude-code-...\resources\native-binary\claude.exe`. Их нужно добавлять в `ProtectedApps` отдельными строками и применять firewall-правила. После обновления расширения папка с версией меняется; приложение распознаёт этот формат и должно показать `Путь устарел` с кнопкой `Обновить путь`. Если без VPN Marketplace даёт `Failed to fetch`, но чат всё ещё отвечает `403 Forbidden` с `cf-ray`, это не успешная блокировка: запрос дошёл до сервера через незакрытый helper. Хороший fail-closed сигнал: `Failed to fetch`, timeout, `ERR_CONNECTION...`, `stream disconnected ... error sending request`.
- По-прежнему **не** подходит для приложений, которые ходят в сеть через **общий `node.exe`** (или другой общий хост-процесс): заблокировать общий `node.exe` нельзя — это перекрыло бы все Node-программы разом, а не одну.
- Это **не** перехват трафика и не VPN-клиент: приложение только создаёт/снимает firewall-правила и читает их состояние.

### Ручная проверка (тест-сценарий)

1. Добавь программу в список (`Добавить программу`), выбери `.exe` (для теста удобен браузер или portable curl).
2. `Применить правила` → проверь список адаптеров на экране подтверждения (там должны быть все твои сетевые пути и не должно быть VPN-адаптера) → подтверди UAC. Статус должен стать `Защищено`, а над кнопками появиться строка «Прямой выход блокируется через: …».
3. При включённом VPN проверь, что программа выходит в интернет.
4. Выключи VPN.
5. Проверь, что программа **не** может выйти напрямую (страница не грузится / таймаут). Контроль: программа, которой нет в списке, при выключенном VPN в интернет выходит — значит блокируется именно защищённая.
6. Включи VPN обратно — доступ восстанавливается.
7. `Удалить` программу из списка → подтверди UAC.
8. Проверь, что правило снято (см. команду ниже — список пуст).

Проверка наличия правил вручную (read-only, без admin):

```powershell
netsh advfirewall firewall show rule name=all dir=out | findstr /C:"VPN Health Monitor"
```

`Get-NetFirewallRule -DisplayName 'VPN Health Monitor - *'` тоже подходит, но только если у тебя он отрабатывает без прав администратора — см. «Пропал интернет — как вернуть» ниже.

### Пропал интернет — как вернуть

Правила kill switch живут в Windows Firewall сами по себе: они продолжают действовать, даже если приложение закрыто, удалено или машина перезагружена. Поэтому «программа не выходит в сеть» может быть следствием давно забытой настройки. Три способа снять защиту, от простого к аварийному.

**1. Из приложения.** Вкладка `Защищённые приложения` → кнопка `Отключить защиту` → подтвердить UAC. Снимаются все правила приложения.

**2. Аварийным скриптом** — когда приложение не открывается, не установлено или непонятно, что происходит:

```text
tools\remove-protection.bat
```

Двойной клик. Скрипт сам запросит права администратора, покажет найденные правила, снимет их и отчитается, сколько осталось. Повторный запуск безопасен: если правил нет, он так и скажет. Проверить, что он собирается удалить, ничего не меняя:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\remove-protection.ps1 -DryRun
```

**3. Руками через `netsh`** — если нет и скрипта. Посмотреть правила (работает без прав администратора):

```powershell
netsh advfirewall firewall show rule name=all dir=out | findstr /C:"VPN Health Monitor"
```

Удалить конкретное правило (нужен PowerShell **от администратора**, имя копируется из вывода выше целиком, вместе с `[hash]`):

```powershell
netsh advfirewall firewall delete rule name="VPN Health Monitor - Block Direct - firefox.exe [016ac999]"
```

**Почему не `Get-NetFirewallRule`.** Раньше здесь была одна команда `Get-NetFirewallRule -DisplayName 'VPN Health Monitor - *' | Remove-NetFirewallRule`, и она подводит ровно в аварийной ситуации:

- без прав администратора командлет падает с `Access is denied` и возвращает **ноль правил** — выглядит так, будто правил нет и снимать нечего, хотя они есть и работают (проверено на живых правилах);
- имена правил содержат `[hash]`, а `-DisplayName` трактует квадратные скобки как wildcard-класс символов, поэтому точное имя таким способом не находится;
- модуля `NetSecurity` может не быть в урезанной или ограниченной политикой среде.

`netsh` показывает те же правила без прав администратора и не страдает ни от одной из этих проблем. От администратора командлет по-прежнему работает — если он у тебя отрабатывает, пользуйся им.

Во всех вариантах удаляются **только** правила с префиксом `VPN Health Monitor - `; чужие правила firewall не затрагиваются.

### Требование к установщику

Деинсталлятор **обязан** снимать правила при удалении приложения — иначе после удаления остаются висячие блокировки, которые никто уже не свяжет с исчезнувшей программой. Готовый вызов, без окон и вопросов:

```text
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<папка приложения>\tools\remove-protection.ps1" -Silent
```

Деинсталлятор работает с правами администратора, поэтому скрипт не будет запрашивать UAC отдельно. Повторный вызов безопасен: если пользователь уже снял защиту из интерфейса, скрипт вернёт `0` и ничего не сделает.

## Настройки и логи

Настройки хранятся локально:

```text
%LOCALAPPDATA%\VpnHealthMonitor\settings.json
```

Логи по умолчанию:

```text
%LOCALAPPDATA%\VpnHealthMonitor\logs\vpn-health-monitor-YYYY-MM-DD.jsonl
```

Путь к логам можно изменить в Settings. Формат логов — JSONL: одна строка на событие. Логируются события, а не каждый сетевой запрос подряд: старт/стоп мониторинга, смена статуса, смена IP, потеря/восстановление интернета, начало/окончание leak risk, degraded и check failed. В событие также попадают IPv6, DNS info и interface/default route, если они есть в последнем snapshot.

`Export CSV` читает JSONL-файлы `vpn-health-monitor-*.jsonl` из папки логов и создает рядом:

```text
%LOCALAPPDATA%\VpnHealthMonitor\logs\vpn-health-monitor-export-YYYYMMDD-HHMMSS.csv
```

CSV содержит: timestamp, status, IPv4, IPv6, country, ASN/provider, ping, packet loss, DNS info, interface/default route, description. JSONL остается основным логом, CSV — удобный экспорт для просмотра в Excel/таблицах.

## Внешние сервисы

MVP вызывает внешние сервисы только для диагностики сети:

- `https://api.ipify.org?format=json` — внешний IPv4.
- `https://ifconfig.me/ip` — fallback для внешнего IPv4.
- `https://ipinfo.io/json` — внешний IPv4, country, ASN/provider.
- `https://ipapi.co/json/` — fallback для внешнего IPv4/country/ASN/provider.
- `https://ipwho.is/` — fallback для внешнего IPv4/country/ASN/provider.
- Если внешний IPv4 получен без страны, приложение дополнительно пробует geo lookup по этому IP через `ipinfo.io/{ip}/json`, `ipapi.co/{ip}/json/` и `ipwho.is/{ip}`. Все адреса — только `https`.
- `https://api6.ipify.org?format=json` — внешний IPv6 через IPv6-only endpoint.
- `https://ifconfig.co/ip` — fallback для внешнего IPv6.
- `https://icanhazip.com` — fallback для внешнего IPv6.
- `https://www.cloudflare.com/cdn-cgi/trace` — HTTP availability.
- `https://www.google.com/generate_204` — HTTP availability.
- `https://www.msftconnecttest.com/connecttest.txt` — HTTP availability.
- ICMP ping к `1.1.1.1` и `8.8.8.8`, если доступен без админ-прав.

**Все эти адреса — настройки, а не константы.** `HTTP-пробы доступности`, `Хосты для ping`, `IP API endpoint'ы` и `IPv6/API endpoint'ы` редактируются в Settings: в сети, где заблокированы Google и Cloudflare, зашитый список означал бы вечное `НЕТ ИНТЕРНЕТА`. Удалённый адрес больше не возвращается сам — раньше приложение дописывало свои значения обратно при каждом сохранении. Полностью пустое поле означает «верни значения по умолчанию».

Если один IP/geo API недоступен, это не считается leak risk автоматически. Приложение отдельно отличает `ПРОВЕРКА НЕ УДАЛАСЬ` от `НЕТ ИНТЕРНЕТА` через HTTP/ping проверки.

## Безопасность и приватность

VPN Health Monitor не является VPN-клиентом, proxy, MITM или traffic sniffer. Приложение не перехватывает трафик, не логирует посещенные URL, не читает пользовательские файлы и не отправляет их наружу. Опционально оно может работать как **per-app kill switch** для выбранных программ (вкладка `Защищённые приложения`) — это не перехват трафика, а только создание/снятие правил Windows Firewall, требующее прав администратора; по умолчанию функция выключена и список пуст. Внешние запросы нужны только для определения публичного IPv4/IPv6/страны и базовой доступности интернета. DNS-серверы читаются локально из сетевых настроек Windows.

## Статусы

- `OK` — интернет работает, внешний IPv4 получен, включенные risk-настройки проходят, ping/loss в норме.
- `НЕТ ИНТЕРНЕТА` — массово не проходят HTTP/ping и внешний IPv4 получить не удалось.
- `РИСК УТЕЧКИ` — интернет есть, но страна не совпадает, expected IP не совпадает, IP изменился при запрете таких изменений, default route ушел с ожидаемого VPN-интерфейса, провайдер выхода вне списка разрешённых или внешний IPv6 виден при запрете IPv6.
- `IP ИЗМЕНИЛСЯ` — страна совпадает, но IP изменился относительно baseline и настройки считают это предупреждением.
- `СТРАНА ИЗМЕНИЛАСЬ` — страна изменилась, но риск по стране выключен.
- `СТРАНА НЕ ОПРЕДЕЛЕНА` — country не удалось определить, но риск по стране выключен.
- `СЕТЬ ПРОСЕЛА` — интернет и IP корректны, но rolling ping/loss выше порогов.
- `ПРОВЕРКА НЕ УДАЛАСЬ` — интернет выглядит доступным, но проверка внешнего IPv4/geo не удалась.
